### Summary

Migrated TCAD Scraper database from Render PostgreSQL (accessed via Cloudflare Hyperdrive) to Cloudflare D1 (managed SQLite at the edge). Eliminates Render dependency; all infrastructure now on Cloudflare.

**Architecture change**:
```
BEFORE: CF Workers (Hono) --> Hyperdrive --> PostgreSQL (Render)
AFTER:  CF Workers (Hono) --> D1 (SQLite) [edge reads, single-region writes]
```

### Critical Issue Discovered: D1 DateTime Type Coercion

D1's JavaScript binding auto-converts date-like TEXT values on read (ISO 8601 `2026-03-30T05:21:24Z` -> `2026-03-30 05:21:24 +00:00`), which breaks Prisma's String type mapping. Multiple fix attempts failed:

1. Changed schema to DateTime -> Prisma generates string TS types for SQLite DateTime, same error
2. STRICT tables -> D1 conversion happens at JS binding level, not SQLite level
3. Prisma ORM for all writes -> Even Prisma-written data gets converted on read

**Final fix**: Store dates as **epoch millisecond strings** (`"1711773684000"`). D1 doesn't recognize numeric strings as dates, so no conversion occurs. Epoch ms strings from 2020-2040 are all 13 chars, so lexicographic string comparison matches chronological order.

### Key Technical Decisions

| Decision | Rationale |
|----------|-----------|
| Epoch ms strings for dates | D1 type coercion breaks ISO 8601 strings; epoch strings are safe |
| Prisma `$transaction` + individual upserts (not raw SQL) | Avoids D1's 100-param limit and id generation issues; handles date serialization correctly |
| SQLite LIKE (no `mode: "insensitive"`) | SQLite LIKE is case-insensitive for ASCII by default; sufficient for TCAD data |
| `sanitizeWhereClause` for AI queries | LLM may still emit `mode: "insensitive"` despite prompt; runtime safety net |
| D1 prepared statements for api-usage | `Prisma.sql`/`Prisma.empty` not supported with D1 adapter |

### D1 Constraints Reference

| Constraint | Value | Impact |
|-----------|-------|--------|
| Max database size | 10 GB (hard) | ~365K properties at ~2KB/row = ~730 MB. Safe now |

### SQL Translation Patterns Applied

| PostgreSQL | D1/SQLite |
|-----------|-----------|
| `$1, $2` numbered params | `?, ?` positional params |
| `ILIKE` / `mode: "insensitive"` | `LIKE` (case-insensitive for ASCII) |
| `(xmax = 0) AS inserted` | Pre-query SELECT existence check |
| `CAST(... AS bigint)` | Remove cast |
| `DATE(timestamp)` | `date(CAST(timestamp AS INTEGER)/1000, 'unixepoch')` |
| `WHEN success` | `WHEN success = 1` |
| `Prisma.sql` / `Prisma.empty` | D1 `prepare().bind().all()` |
| `String[]` array | `String @default("[]")` + JSON.stringify/parse |
| `@default(now())` | `@default("0")` + explicit `nowEpoch()` |
| `@updatedAt` | Explicit `updatedAt: nowEpoch()` in all update calls |
